Integration Endpoints

Læsevenlig oversigt over de tre operationelle integrationssider i Business Central: AuningStockDW, PerfionItemsDW og PerfionPricesDW.

Formål

Dokumentet beskriver forretningsformål, teknisk design, drift i BC og de vigtigste beregningsregler.

Status

Version pr. 2026-04-17. Dokumentet dækker den aktuelle registrering og logik i repoet.

Samlet overblik

Service Formål Datakilde Mønster
AuningStockDW Snapshot af aktuelt lager til eCommerce og integration Item med snapshotfelter Job Queue beregner, OData eksponerer
PerfionItemsDW Kurateret varemaster til Perfion-relateret eksport Item plus relaterede tabeller Direkte OData med enrichment i siden
PerfionPricesDW Kurateret prisfeed med gyldige priser og kampagnepris Price List Line og Campaign Temporary dataset bygget ved kald
Perfion-området har fortsat de to custom API-sider PerfionItemsAPI og PerfionPricesAPI i appen. Den aktuelle operative publicering til DW-flowet sker dog via OData-siderne.

1. AUNING Stock

Scope

  • Lokation: AUNING
  • Kun inventory items
  • Produktbogføringsgrupper: INTERN|EKSTERN|BRUND

Felter

  • itemNo
  • description
  • auningStockOnHand
  • auningStockAvailable
  • auningStockUpdatedAt

Driftsmønster

  • Snapshot beregnes af Job Queue
  • Gemmes på Item
  • Vises også i FactBox på Item Card

Beregning

AUNING Stock On Hand beregnes fra Item.Inventory pr. lokation og variant. AUNING Stock Available beregnes via Warehouse Availability Mgt. og kan reduceres med en bufferprocent.

  • Blank variant og eksplicitte varianter summeres
  • Alle mængder rundes ned til heltal
  • Negative værdier clamps til 0
  • Ét fælles timestamp gemmes for hele kørslen

Job Queue-parametre

GenProdPostingGroupFilter=INTERN|EKSTERN|BRUND
GenProdPostingGroupFilter=INTERN|EKSTERN|BRUND;AvailableReductionPct=10
GenProdPostingGroupFilter=INTERN|EKSTERN|BRUND;AvailableReductionPct=10;ScheduledMinute=50

AvailableReductionPct=0 betyder ingen ekstra reduktion. AvailableReductionPct=10 betyder 10% reduktion af den beregnede disponibele beholdning. ScheduledMinute=50 betyder, at jobbet selv normaliserer sig til hourly recurring på alle dage og kun udfører lageropdateringen i minut 50. Hvis jobbet genstartes eller driver væk fra det konfigurerede minut, justeres næste kørsel tilbage til næste XX:50.

Operationelt lag i BC

  • Planlægges som Job Queue mod codeunit 50042 "Auning Stock Update"
  • Med ScheduledMinute håndhæver codeuniten selv hourly schedule på alle dage
  • Ved manuel kørsel med UI vises progress-dialog
  • Snapshotfriskhed kan kontrolleres direkte på Item Card FactBox

2. Perfion Items

PerfionItemsDW leverer en kurateret item-master til integration. Siden læser direkte fra Item, men beriger hver række med data fra relaterede tabeller.

Basefilter

  • Gen. Prod. Posting Group = INTERN|EKSTERN|BRUND
  • ABCD Category <> E og <> D
  • Product Usage <> PRODUCTION og <> MARKETING
  • Prod. Group Code <> RÅVARE

Berigelse pr. række

  • Type som både integer og tekst
  • Barcodes for STK, INNER og MASTER
  • Oversatte beskrivelser i flere sprog
  • Fallback til Item.Description for dansk tekst
  • Mål, vægt og quantity per unit of measure for tre UoM-niveauer

Datakilder

  • Item
  • Item Reference
  • Item Translation
  • Item Unit of Measure

3. Perfion Prices

PerfionPricesDW er et kurateret prisfeed. Siden bygger et midlertidigt datasæt ved hvert kald og returnerer den foretrukne gyldige prislinje for i dag plus eventuel kampagnepris.

Udvælgelseslogik

  1. Kun aktive prislinjer for dags dato tages med
  2. Kun Asset Type = Item og Source Type = Customer Price Group bruges som basis
  3. Der beholdes én række pr. kombination af item, sales code, valuta og UoM
  4. Seneste Starting Date vinder
  5. Ved samme startdato vinder laveste Unit Price

Kampagnelogik

  • Søger kampagnelinjer i Price List Line med Source Type = Campaign
  • Matcher mod salgskode via Campaign."Customer Price Group NOTO"
  • Vælger laveste gyldige kampagnepris
  • Ved lighed vinder seneste Starting Date
Den nuværende deduplikeringsnøgle inkluderer ikke Minimum Quantity. Derfor er endpointet designet som et kurateret prisfeed og ikke som et fuldt tier-prisudtræk.

Publicering og rettigheder

Publiceringen styres centralt af DW WS Registrar, som rydder gamle web service-rækker og opretter én kanonisk publicering pr. side.

  • AuningStockDW
  • PerfionItemsDW
  • PerfionPricesDW

Integrationbrugeren skal have adgang til både siderne og de underliggende tabeller via de relevante permission sets.

Schema-stabilitet

Tekniske feltnavne på installerede tabeller er schema-kontrakter i BC. Caption-ændringer er sikre, men omdøbning af tekniske feltnavne er ikke sikker under normal Synchronize.
  • Business Central opfatter et teknisk feltrename som fjernelse plus ny oprettelse
  • Det kræver upgrade-strategi eller tvungen sync i et kontrolleret ikke-produktionsscenario
  • Det gælder også snapshotfelter, selv om indholdet kan genberegnes

Kodeeksempel

Uddrag fra stock-normaliseringen:

local procedure NormalizeAvailableQuantity(AvailableQuantity: Decimal; AvailableReductionPct: Decimal): Decimal
var
    ReducedAvailableQuantity: Decimal;
begin
    ReducedAvailableQuantity := AvailableQuantity;
    if AvailableReductionPct > 0 then
        ReducedAvailableQuantity := ReducedAvailableQuantity * (100 - AvailableReductionPct) / 100;

    exit(NormalizeQuantity(ReducedAvailableQuantity));
end;

Forklaring: den beregnede disponible beholdning reduceres kun, hvis parameteren er større end 0. Derefter normaliseres resultatet til heltal og minimum 0.
